# Translations (i18n)

How texts are written in the code, and how a language is added or fixed.

## Files

| Path | What |
|---|---|
| `src/i18n/messages/en.ts` | English, the reference: every key is here first |
| `src/i18n/messages/<code>.ts` | one file per language, same keys (`it`, `de`, `es`, `fr`, `pt-BR`, `hi`, `zh-Hans`) |
| `src/i18n/locales.ts` | the list of languages, browser-language matching, the default |
| `src/i18n/core.ts` | lookup, plurals, placeholders, Intl formatting (no Vite, no browser: Node runs it too) |
| `src/i18n/index.ts` | the site's side: current languages, `t()`, lazy loading, saved choice |
| `src/i18n/react.tsx` | `useT()`, `<Trans>`, `<LocaleBoundary>`, `<LanguageSwitcher>` |
| `scripts/i18n.mjs` | the same translations for the Node scripts of the workflows |

English and Italian are in the bundle; every other language is its own small file, downloaded when
chosen (and kept by the service worker for offline use).

`it.ts` must have every key (TypeScript checks it): it is the language of the first tournament and
its texts must stay exactly as they were. The other languages may miss keys while they are being
translated: a missing key shows in English. `src/i18n/__tests__/i18n.test.ts` checks every file:
no key English does not have, the same `{placeholders}`, lists where English has lists.

## Leaves

```ts
// a text with placeholders
wins: '{winner} beats {loser}',
// a plural, by the `count` param, with the CLDR categories of the language; "=0" is an exact match
games: { '=0': 'no games', one: '{count} game', other: '{count} games' },
// variants: the group messages pick one at random (tList)
roundEnd: ['🏁 *Round {round} is over!*', '🏁 *Round {round}: all the results*'],
```

A section never has a key named `other` (it would read as a plural).

## Two languages

- **The viewer's language**: what the site shows. Saved choice, else the browser's languages, else the
  tournament's. `t()`, `tList()`, `formatDate()`… use it.
- **The tournament's language**: what goes to the group chat (round message, status bulletin, awards
  message), the language the AI prompts ask for, the link preview. Use `groupTranslator()`: an
  organizer browsing in English still prepares Italian messages for an Italian group.
- Push notifications: in the language of whoever subscribed.
- Texts written by the organizer (rules, anecdotes, presentation of the master, season names) are
  data: shown as written.

## Writing code with texts

```ts
import { t, groupTranslator, formatDate } from '../i18n';
t('public.standings.leader', { name, points });            // the viewer's language
const g = groupTranslator();                               // the tournament's language
g.t('messages.bulletin.header', { round });
g.tList('messages.bulletin.win');                          // the variants of a phrase
```

In React, `const { t, formatDate } = useT();` re-renders on a language change. A sentence with a link
or a bold name inside:

```tsx
<Trans k="chronicle.result.win" params={{ winner: <PlayerLink handle={w} />, loser: <PlayerLink handle={l} /> }} />
```

Rules:

- **One key per sentence**, with `{params}`. Never glue translated pieces together: word order
  differs between languages ("vince Anna" / "Anna wins" / "Anna gewinnt").
- Names, handles, numbers, dates and links are params. WhatsApp markup (`*bold*`, `_italic_`) and
  emoji are part of the translation.
- Numbers through `formatNumber` (Italian "1,5", English "1.5"), dates through `formatDate` /
  `formatTime`, lists through `formatList` ("Anna, Bruno e Carla"), sorting names through
  `compareText`. Never `'it-IT'` in the code. Where today's code says `timeZone: 'Europe/Rome'`, keep
  the option: the tournament's time zone becomes configurable in phase 2.
- Plurals through a plural leaf, never `n === 1 ? … : …` in the code.
- Pure functions in `src/lib/` that build sentences for the group take a `Translator` argument
  (default `groupTranslator()`), so tests can pass one.
- Keys are named by meaning, not by wording: `public.standings.title`, not `public.classifica`.
  Shared words go in `common`.
- Machine identifiers stay as they are, even when they are Italian words stored on Firestore
  (`source: 'backup automatico'`, award ids, `andata`/`volata`/`finale`…): changing them would break
  the data already saved. Translate what is shown, not what is stored.
- Archived seasons store some texts in Italian (award `title`, `description`, `detail`): show the
  translation from the award `id` and its numbers when they can be rebuilt, the stored text otherwise.

## Golden tests

`tests/golden/` renders every public view, every player page, the organizer tabs, the group messages,
the prompts and the push notifications in four scenarios (`scenarios.ts`, from the anonymised
`tests/fixtures/tournament.json`), as plain text in `tests/golden/it/`. The Italian output must not
change: after moving texts into the translation files, `npx vitest run tests/golden` must pass
untouched. If a text you are about to move is in none of the golden files, add it to
`golden.test.tsx` **before** changing the code. A wanted change (reviewed) is written with
`npx vitest run tests/golden -u` and shows in the diff.

## Adding a language

1. An entry in `LOCALES` (`src/i18n/locales.ts`): code, name in the language itself, Intl locale.
2. `src/i18n/messages/<code>.ts`, copied from `en.ts` as `DeepPartial<Messages>`, then translated.
   Chess terms as Lichess uses them in that language.
3. `npm test`: the translation-file test reports unknown keys and wrong placeholders.
4. Check the narrow phone layout (375 px): some languages are much longer than English.
